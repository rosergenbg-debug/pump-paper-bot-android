# X — архив Windows-стратегий с записанным результатом от +80%

Снимки основной истории сделаны 10.09.2026; сохранение и проверка завершены 12.09.2026.
Это **архив исследовательских результатов Pump.exe**, добавленный по прямому поручению владельца.
Старые X/T32 checkpoints остаются на месте. Архив не присваивает стратегиям торговые полномочия.

## Что именно сохранено

- **23 786 версий записей** с доходностью от +80% хотя бы в одном сохранённом общем показателе.
- **37 370 версий записей всего**, включая связанные прежние/повторные расчёты с меньшей доходностью.
- **25 568 разных ID**, в том числе переименования между версиями; это не число независимых алгоритмов.
- **9 654 точных набора полных параметров**. Разные наборы могут давать одинаковые сделки.
- **25 725 записей с полными доступными подробностями**. Для каждого ID существует хотя бы одна такая запись; отдельно сохранены сокращённые состояния после очистки.
- 20 источников SQLite: согласованные снимки рабочих баз, базы из резервной копии до очистки и старая копия на C:.
- 78 файлов исходных рыночных данных и описаний, включая точные PUMP/BTC/SOL 1m JSONL, development и исходные holdout-разбиения. Сжатие gzip обратимо побайтно.
- Сохранённые отчёты, checkpoints, параметры кампаний, политика использования истории, схемы SQLite, происхождение каждой строки и SHA-256.
- Скомпилированные реализации V7.1, V7.2, V8.0, V13, V14, V15, V16, их дизассемблирование, доступные редактируемые исходники и оболочка V17.1.

Точное определение отбора: `development_compound`, `best_development_compound`, `worst_net`, `regimes.*.metrics.compound_net` либо доходность `preview.final / preview.initial - 1` не меньше `0.8`.
Это порог **NET/капитала, не win rate**. Не требуется +80% на всех трёх рынках: иначе можно было бы потерять ранний результат около +200% на одном периоде.
Сегментные TRAIN/VALIDATION метрики сами по себе не используются как общий результат для отбора.
Все связанные версии найдены по одинаковому ID без префикса Vxx или по точному хешу конфигурации. Это связь происхождения, а не утверждение эквивалентности движков.

## Быстрый вход для другого AI

1. Прочитать этот README, [полный контекст и ограничения](FULL_REPORT_RU.md), затем [инструкцию воспроизведения](RESTORE_RU.md).
2. Найти ID в [INDEX.csv](INDEX.csv). Каждая строка содержит хеш конкретной версии, файл с записью, показатели и источники.
3. Получить все версии нужного ID командой `archive.py extract`; получить читаемый полный отчёт командой `archive.py report`.
4. Проверить [MANIFEST.json](MANIFEST.json) командой `archive.py verify --deep`.
5. Восстанавливать только в новые каталоги. Выбрать исходную версию движка, исходные параметры, правильные периоды и хеши данных.
6. Сравнить повтор с сохранёнными показателями; любое расхождение записать отдельно. Старую запись никогда не исправлять задним числом.

Стартовые примеры: [около +200%](examples/AE3427777B1.md), [+201,17%](examples/ACBC1861A31.md), [+211,87%](examples/A13E13EE32A.md), [+87,96%](examples/AE6B6617FE9.md), [+80,61%](examples/A31BC71B331.md).

## Что означает «полный отчёт» здесь

Для каждого найденного ID сохранены **все обнаруженные доступные поля**, параметры и варианты записи. В BLOB сохранены исходные байты SQLite, дополнительно дан читаемый JSON. Где присутствовали метрики TRAIN/VALIDATION, траектория капитала, причины выхода, оценки, флаги допуска и история повторов, они включены без сокращения.

Но прежние базы не всегда хранили каждую цену и время входа/выхода. Архив не выдумывает отсутствующий trade ledger. Для V9–V12 не обнаружены отдельные точные исходные сборки; имеющиеся V13+ нельзя молча объявлять их заменой. Редактируемые исходники старой рабочей папки отличаются от поздних EXE — статус указан явно. Поэтому побайтная сохранность архива подтверждается отдельно от возможности повторить каждый старый процент.

## Проверенный пример

Из восстановленных данных и сохранённого движка V16 повторён `V16-fc6d22261c18944a`:
BEAR **+95,22867709%**, SIDEWAYS **+88,41406230%**, BULL **+88,41406230%**.
Все сохранённые агрегированные метрики каждого из трёх рынков совпали с повтором.
Подробности: [проверки](VERIFICATION.json). Это один проверенный replay, а не проверка прибыльности всех записей.

## Не терять

Архив неизменяемый: дальнейшие исправления и исследования — новым датированным дополнением.
Не переименовывать V13/V14/V16-результаты в V17.1. Не удалять меньшие повторные результаты.
Не суммировать доходности пересекающихся рынков. Не трактовать старый просмотренный TEST как независимый.
Выгрузка не содержит API-ключей, подписывающих ключей или пользовательских SQLite-баз целиком: только отобранные строки и относящийся к исследованию контекст.
