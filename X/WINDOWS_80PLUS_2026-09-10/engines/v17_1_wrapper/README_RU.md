# PUMP Research Lab V17.1 — восстановленная V16, локальные базы

Это исправление неудачной урезанной V17-preview. За основу возвращена полная
V16: её выбор рынков, многопроцессорный поиск, пауза, продолжение, архив,
повторные проверки, отчёты и экспорт. Торговый алгоритм не заменён.

## Запуск

Распакуйте папку целиком отдельно от старых EXE. Запускайте
`PumpResearchLab-V17.1-Restored.exe`; папка `_internal` рядом обязательна.
Не копируйте её содержимое поверх `_internal` старой V16.
Хранилище по умолчанию: `F:\PUMP Research Lab`. Без диска F программа
покажет ошибку, а не создаст пустую замену на C. V16 одновременно не запускать.

1. На главной уже отмечены **Падение + Боковик + Рост**, по **6 месяцев**.
2. Нажмите жёлтую кнопку: проверка местных файлов → поиск / продолжение.
3. Можно отдельно проверить файлы и отдельно начать расчёт.
4. Выбирайте профиль CPU: максимум / быстро / фон. Число процессов определяет
   оригинальная аппаратная логика V16, а не фиксированные два процесса preview.
5. «Пауза» и «Сохранить и остановить» используют прежние checkpoints.

## Интернет-загрузки отключены

По последнему указанию владельца новые базы не скачиваются. Возраст старого
комплекта не мешает повторному исследованию. Если нужного комплекта нет, программа
сообщит об этом и не будет ничего скачивать. Ручной выбор новых дат убран именно
из этого локального режима; доступны сохранённые комплекты.

При старте проверяются контрольные суммы, число свечей, пропуски и совпадение
периодов PUMP/BTC/SOL. Биткоин и Solana нельзя подставлять из других дат.
Проверенные комплекты по 259 200 минут на каждую монету:

- Падение: 16.09.2025–14.03.2026.
- Боковик: 05.02.2026–03.08.2026.
- Рост: 25.02.2026–23.08.2026.

Периоды пересекаются. Это стресс-исследование, не независимые три TEST.
Во вкладке «Базы данных» видны сохранённые комплекты, периоды, объёмы и пути;
ниже — девять файлов трёх выбранных контекстов.

## Журнал от +50% на каждом рынке

Полные находки попадают в журнал только при NET >= 50% в BEAR, SIDEWAYS и BULL.
Один рынок с +100% при слабых остальных не проходит. Старые версии сохраняют
свои идентификаторы и ограничения расчёта: высокий процент не означает торговый допуск.

По подтверждённому указанию владельца подробности остальных архивных вариантов
очищены. Остаются короткие служебные записи ID/семейство/оценка, чтобы сохранить
счётчик, обучение и не повторять уже проверенные варианты. Отдельно сохраняются
40 рабочих лидеров каждого опыта — именно столько использовал исходный V16.
Это не лимит числа проверок и не пользовательский журнал. Незавершённые задания
сохранены; очистка не обнуляет опыт.

График текущего поиска может показывать результат ниже +50%: это рабочий лидер,
а не запись в журнале. Служебные V16 LIVE-отчёты также сохраняют диагностическую
информацию исходного алгоритма и перезаписываются, не накапливая все промежуточные версии.

Рыночные базы, экспортированные модели, старые файлы отчётов и EXE V16 не удалены.
Резервная копия до очистки хранится отдельно в рабочей папке Codex:
`v17_restored/rollback-before-50pct-20260909` или архиве ZIP с тем же именем.
Восстановление SQLite делать только при закрытых программах, не копировать
основной файл поверх активного WAL. После очистки рекомендуем работать в этой сборке:
старая V16 снова начнёт записывать находки по прежнему порогу.

## Телеметрия и проверки

CPU/GPU/RAM и температуры — общая нагрузка компьютера. Точный replay работает
на CPU; GPU может быть загружена другим приложением. Недоступный датчик не
подменяется нулём. На этом компьютере температура CPU получена из MSI Afterburner.

Проверены: полное подключение трёх старых баз и девяти файлов без интернета,
видимость старого архива, датчики, автоматический переход к прежнему поиску,
реальный ограниченный replay на трёх полных окнах с двумя процессами, порог журнала,
очистка, сохранение оценок/лидеров и отсутствие повторной выдачи выполненных ID.
Это проверки работоспособности, а не обещание будущей прибыли.

Окончательный EXE проверен двумя отдельными запусками. Дополнительно из EXE
выполнен реальный replay одного заданного варианта на трёх полных периодах
с двумя процессами и новым адаптером журнала. 11 автоматических тестов пройдены.
Подробная точка восстановления и итоги очистки — в `CURRENT_STATE.md`.

## Для продолжения разработки

`bootstrap.py` проверяет SHA-256 всех 34 извлечённых модулей V16. Они не изменены.
`restored_app.py` наследует полное исходное окно; `theme.py` отвечает за вид.
`offline_data.py` — только чтение и проверка существующих данных.
`journal.py` явно подключает адаптер хранения, не меняя replay/reward/ranking V16.
Часть исходников V16 остаётся скомпилированной зависимостью Python 3.13.
Не заменять полную программу новой узкой оболочкой.

Сборка: Python 3.13, PySide6 6.9.3, DuckDB 1.5.5, PyInstaller 6.16.0.
`python -m unittest discover -v`, затем сборка из приложенного `.spec`.
Рядом с `v17_restored` требуется `recovery_v16/compiled` и `manifest.json`.
