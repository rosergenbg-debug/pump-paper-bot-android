# Восстановление другим AI или разработчиком

## 1. Получить архив и проверить его

Клонировать репозиторий `rosergenbg-debug/pump-paper-bot-android` или скачать целиком архив GitHub. Рабочая папка далее: `X/WINDOWS_80PLUS_2026-09-10`.
Для проверки и распаковки достаточно Python 3.12+ и стандартной библиотеки. Для сохранённого bytecode нужен именно Python 3.13.

```text
python archive.py verify --deep
```

Проверка включает SHA-256 всех файлов, содержимое каждой версии записи, исходные SQLite BLOB, покрытие индекса, количество записей и распакованные bytes всех наборов.

## 2. Прочитать все варианты интересующей стратегии

```text
python archive.py extract --id AE3427777B1 --output restored/AE3427777B1.json
python archive.py report --id AE3427777B1 --output restored/AE3427777B1.md
```

JSON содержит **все найденные версии ID**. Выбрать запись по `record_sha256`, происхождению, дате и версии движка. Не брать автоматически максимальную цифру. Полный каталог: `INDEX.csv`; параметры и исходные результаты: `records/part-*.jsonl.gz`.
Поля долей хранятся как дроби: `0.8 = +80%`, `1.9987033191822694 = +199.87033191822694%`. `None/null` не заменять нулём или доказанной бесконечностью.

## 3. Восстановить исходные строки SQLite

```text
python archive.py restore-db --source live/checkpoints/automatic-6m-bear-f8ccb2a670bc977c-interesting.sqlite3 --output restored/bear.sqlite3
```

Допустимые имена источников и схемы указаны в `SOURCE_DATABASES.json`. Создаётся **подмножество отобранных строк**, а не полная рабочая очередь кампании. BLOB восстанавливается из base64 без изменений. Утилита не перезаписывает существующие файлы и не изменяет оригиналы.
Нельзя выдавать это подмножество за весь старый прогресс поиска. Для чтения использовать отдельное хранилище.

## 4. Восстановить точные данные

```text
python archive.py restore-data --output restored/market
```

Все 78 файлов будут восстановлены с исходными относительными путями и контрольными суммами. Для выборочной распаковки можно указать `--prefix data/raw/binance_spot/PUMPUSDT/`.
В JSON-описаниях остаются старые абсолютные пути C:/F: — это часть исходных байтов. Переназначать пути только в отдельной рабочей копии, не редактировать архивные описания. `replay_record.py` делает это в памяти для трёх стандартных полугодовых наборов.
Holdout копируется как исторический материал, но не становится новым невиданным TEST.

## 5. Повторить проверенный вариант V16

Создать отдельное Python 3.13 окружение и установить зависимости из `engines/requirements.txt`.
Не смешивать пакеты `pump_research_lab` разных каталогов engines и не копировать bytecode в рабочую V16.

```text
python archive.py extract --id V16-fc6d22261c18944a --output restored/v16.json
python replay_record.py --engine v16 --record restored/v16.json --record-hash 3e40167ac4bb11ec81ccdd7f191066ab1dbd559f158c76aa295e7cafaae05ac2 --data restored/market --output restored/replay-v16
```

Скрипт требует новый каталог результата, проверяет все модули, соответствие ID версии и точный набор полей. Используется один CPU worker, одна фиксированная конфигурация, три стандартных периода и начальный капитал 1000. AI-предложения отключены; поиска новых параметров нет.
Ожидаемые compound NET: BEAR `0.9522867708550757`, SIDEWAYS `0.884140623009378`, BULL `0.884140623009378`. Сравнивать также fills, WR, average_net, PF, exits, drawdown, CVaR и разбиения, а не только финальный процент.

Скрипт рассчитан на стандартные BEAR/SIDEWAYS/BULL наборы. Для PERIOD_1/2/3 или V12-срезов нужен отдельный явно заданный адаптер периодов по исходным manifests; запускать их как стандартные окна нельзя.

## 6. Старые варианты A* и другие версии

У A*-кандидатов version provenance бывает неполной: сохранены checkpoint engine name, полный config, сегментные метрики и старые compiled references V7.1/V7.2/V8.0, но нет доказательства, что каждый найденный EXE является точной исходной сборкой кандидата.
Именно поэтому готовый harness отказывается молча запускать A* в V16. Следующий разработчик должен сопоставить схему параметров, checkpoint engine, интервалы и старую функцию `adaptive_optimizer._evaluate_config/replay_adaptive` с сохранённым дизассемблированием.
При отсутствии точного билда явно обозначить повтор как перенос на другую версию, сохранить оба результата и список различий. Нельзя обещать точное повторение +199.87% по иной механике.

## 7. Как добавлять продолжение

Не изменять сохранённые record hashes и исходные поля. Новые тесты помещать в отдельный датированный каталог X с parent record hash, хешем кода/данных, полными параметрами, периодами, расходами, trade ledger и сравнением старого/нового результата. При появлении исправленного движка старые проценты остаются историей, а не «исправляются» задним числом.
